# ADR-0017: The reference deployment is the image on AWS behind Cloudflare, written as a skill, and the code stays cloud-neutral

- Status: Accepted
- Date: 2026-10-11

## Context

Milestone 8 of the [roadmap](../roadmap.md) ends with the console deployed next to a managed PostgreSQL and a bucket. [ADR-0002](0002-one-image-one-database-and-the-main-repositorys-toolchain.md) keeps the cloud out of the code, and [`deploy/README.md`](../../deploy/README.md) says what a platform must provide; nothing said how a person who is not a developer gets from an empty cloud account to a console their organization signs in to. The organization's other skills already come to agents through SkillCDN, and the console's own skills live here ([ADR-0015](0015-the-consoles-skills-live-in-this-repository-in-the-skillcdn-format-and-the-package-carries-them.md)); the reference skill repository has a deploy skill for its own platform whose shape (questions asked once, a plan with its cost, resources, secrets, a first deploy, a domain, deploys on push, a record in the project) is what a deployment of the console needs too.

What the deployment must be, from the people who will run one: cheap for one person and still right for a hundred, easy to operate without a developer, serverless where that lowers cost or work, and priced before anything is made, with a choice of sizes. The two clouds the organization uses are AWS and Cloudflare. AWS App Runner, the obvious managed container service, stopped taking new customers on 2026-04-30 and was never in every region; Amazon ECS Express Mode, which AWS names as its successor, provisions a load balancer the console does not need when Cloudflare is in front.

## Decision

1. **The reference deployment is the image on AWS behind Cloudflare, and a skill does it.** [`skills/deploying-a-console`](../../skills/deploying-a-console/SKILL.md) takes an agent, on the person's own machine, from an AWS account and a domain on Cloudflare to a console that is signed in to, with its first project and its first file handed in and read back, and leaves a repository that redeploys on push and a record of what exists. It asks the organization's size, the domain, how people sign in and who is in, and shows the monthly estimate of each size before anything is made.
2. **The shape.** The image runs as tasks on ECS with Fargate in the account's default VPC, with no load balancer: a Cloudflare Tunnel connector beside the `api` container carries the console's hostname into the task, so nothing of the deployment listens on the internet, Cloudflare terminates TLS and limits requests per client, and the client's address arrives in a header from a peer on the loopback. PostgreSQL is RDS, one instance in one zone sized by the organization, private, reached over TLS with the platform's authority given as `DATABASE_CA`. Files go to an S3 bucket with the console's own keys ([ADR-0016](0016-the-bucket-is-reached-through-the-s3-api-with-the-consoles-own-signing-and-reads-what-the-rows-kept-before-it.md)). Secrets live in SSM Parameter Store and reach the tasks as environment variables. The image is built by GitHub Actions in a deployment repository of the organization's own, from a pinned commit of this repository, pushed to ECR; a push to that repository runs `migrate` as a one-off task and then rolls the `api` and `worker` services, as the rollout contract says.
3. **Three sizes, one shape.** Up to ten people: one `api` task carrying the worker's work, the smallest database. Up to thirty: a larger task, a larger database. Up to a hundred: two `api` tasks and a `worker` of its own, a database with room, optionally in two zones. Growing is a change of numbers in the deployment repository and one command for the database, not a new deployment.
4. **The code names no cloud, still.** The one thing the deployment asked of the code is `DATABASE_CA`, the authority a managed database's certificate is checked against, handed in as text for a platform that mounts no files; it is as neutral as `DATABASE_URL`. Every other platform deploys from `deploy/README.md` as before. The organization's own deployment, its accounts, hostnames and sizes, stays outside this repository ([AGENTS.md](../../AGENTS.md), rule 8); the skill carries placeholders and the way to find today's values.
5. **Serverless where it pays.** Fargate is the serverless compute: no instance is managed, and a task is billed by its size and time. The database is a provisioned instance by default because the console holds a listening connection and sweeps on a schedule, which keeps a serverless database from pausing, so Aurora Serverless v2 would cost more than the smallest instance below a few dozen people; the skill offers it where an organization wants capacity that follows load without resizing. Functions are not a fit: the roles are long-lived (a feed, a listener, a sweep).

## Consequences

- A person who is not a developer deploys the console by answering a few questions and doing the few steps only a signed-in person can do (an access key, a token, an OAuth app), with the cost in front of them first; the agent does the rest and leaves a record.
- The deployment is cheap at one person (the task, the smallest database, a public address for egress, Cloudflare's free plan) and does not change shape at a hundred.
- A push to the deployment repository is a deployment: operating the console is editing a file in that repository and pushing, or running the skill again for a new size or a new version.
- Rejected: AWS App Runner (closed to new customers since 2026-04-30, in maintenance, and absent from several regions); ECS Express Mode as the default (a load balancer the tunnel makes unnecessary, at a fixed monthly cost of its own, and a load balancer whose configuration ECS owns; it stays the shape for an organization that wants a load balancer without Cloudflare in front); AWS Lambda (the roles are long-lived); Lightsail containers (no secret store, no one-off tasks); a virtual machine with compose (the cheapest, and nobody's to patch and back up); Cloudflare Containers (no managed PostgreSQL to put beside them); Cloudflare Access in front of the console (a second sign-in, which `console login` cannot pass); the deployment definitions as files in this repository (rule 8, and a cloud named in the code).
