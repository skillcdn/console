# ADR-0056: A record that names the person who did a thing names the agent they did it through

- Status: Accepted
- Date: 2026-11-06

## Context

People decide; agents work ([architecture](../architecture.md)). Since a token became its person on the board ([ADR-0021](0021-a-token-configures-as-its-person-does.md)), every event in the feed has named the agent beside the person, and most records did too: a run names its agent, a comment the agent it was written through ([ADR-0024](0024-a-task-carries-a-discussion-of-comments-with-their-files-read-as-one-thread-with-the-runs-and-the-decisions.md)), a document's versions and its files theirs, a plugin's records their writer's. A decision named the run that raised it, with its agent, and the plugin ([ADR-0052](0052-a-plugins-board-is-a-project-made-or-chosen-when-it-is-enabled-and-what-it-puts-there-carries-its-name.md)), but its answer named the person alone. `console answer` writes an answer in the person's name through their agent, as ADR-0021 asked, so that a choice made in chat or in a meeting reaches the record; the record then read as if the person had answered on the pages, and only the feed's `decision.answered` event, which the pages that show a decision do not read, said otherwise. What followed a decision named nobody at all. A goal named who set it and a task whose it is, each without the agent, where the task did name the plugin that made it. For an audit the difference is the point: whether a person chose, or their agent wrote what it took to be their choice, is what such a record exists to tell.

## Decision

1. **A record that names the person who did a thing names the agent they did it through.** Beside the person, `agent`: the name of the token when the person acted through one, `null` when they did it themselves on the pages; and the plugin, where one acted ([ADR-0052](0052-a-plugins-board-is-a-project-made-or-chosen-when-it-is-enabled-and-what-it-puts-there-carries-its-name.md)). The feed is no longer the only place that says so: the record people read says it, on the pages, in the command and in the API, and a new record of a person's doing carries it from the start.
2. **The decision's answer and what followed carry it.** `answer.agent`; and `outcomeBy`, `outcomeAgent` and `outcomeAt`, written with the outcome and cleared with it (`answered_agent`, `outcome_by_id`, `outcome_agent`, `outcome_at`). A goal carries `agent`, the agent it was set through, beside `createdBy`; a task carries `agent`, the agent it was written through, beside `owner`, whose hands may have changed since, and beside `plugin`.
3. **What the rows did not know, the feed tells them once.** The migration fills the new columns from the events that recorded the same acts with their agent: `decision.answered`, the latest `decision.updated` that named `outcome`, `task.created`, `goal.created`. The records of the past read as the records of today.
4. **Read as optional, answered always.** Each new field is optional in the package's schemas, so that a console built on the package still reads an older console's records, and this console answers every one.
5. **Subjects stay subjects.** A record that names a person as what the act was about, not as who did it, names no agent: a project's member, a task's worker, a decision's decider, a plugin role's holder. The feed names who added them, and through what. A document's `createdBy` names no agent either; its first version does. The rows nobody reads, who listed a login and who started a pack's connection, stay as they are with the feed as their record, and the approval of an agent's connection is a person's own, signed in, and can carry no agent.

## Consequences

- The pages say `answered through <agent>` and `wrote what followed through <agent>` on a decision, `through <agent>` beside who set a goal, and `Written through` on a task; the command prints `through <agent>` beside the login and `written through:` on a task; `console help answer` says the record names the agent beside the person.
- `RestDecision.answer` gains `agent`; `RestDecision` gains `outcomeBy`, `outcomeAgent` and `outcomeAt`; `RestGoal` and `RestTask` gain `agent`. Migration 0033 adds the columns and fills them from the feed.
- Rejected: the feed as the only record (the pages that show a decision do not read it, and an audit should not have to join two records to learn one fact); a flag alone, without the agent's name (the name is what tells one of a person's agents from another, and the feed has it); the agent on subjects (a member added through an agent is still the member, and who added them is the feed's to say).
