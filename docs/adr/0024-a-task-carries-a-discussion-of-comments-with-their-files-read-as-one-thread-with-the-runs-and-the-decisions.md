# ADR-0024: A task carries a discussion of comments, with their files, read as one thread with the runs and the decisions

- Status: Accepted
- Date: 2026-10-13

## Context

A task had its body, the runs on it with their reports and what they handed in, and the decisions about it. What a person wanted to say about the task, a question to the agent, a remark on what was handed in, a screenshot of what was meant, had no place: it went into the body, which is the work order, or into a decision, which waits for an answer, or into a chat outside the board, where the record is lost and the next agent does not see it. An agent with a question that was not a decision had only a report, which is the run's record and needs a run open. Pictures reached nobody: the pages showed only pictures over https from elsewhere, and an agent could not read a file of the board without a token in its hands.

## Decision

1. **A task carries a discussion.** A comment is a word about the task, by a person or by their agent, in Markdown, with the files put in it. Whoever may work in the project writes one; whoever may see the project reads them. A comment is never rewritten or deleted: a mistake is corrected in the next one, as a report is, so that what people and agents read stays what was said. At most `MAX_COMMENTS_PER_TASK` on one task.
2. **The files are the blob store's, as the other files are.** A comment's files are rows of their own (`comment_files`) that name a hash, as a run's artifacts and a page's files do; the bytes are kept once under their hash, in the rows or in the bucket ([ADR-0016](0016-the-bucket-is-reached-through-the-s3-api-with-the-consoles-own-signing-and-reads-what-the-rows-kept-before-it.md)). Each file is checked as a file handed in is, at most `MAX_FILES_PER_COMMENT` of them and together at most `MAX_FILE_BYTES` on one comment. A sweep of files nothing refers to stays open, as before.
3. **One request, one comment, one event.** A comment with files is sent as one form, the part `body` and a part `file` per file, read whole and found good before any byte is kept; without files, as JSON. The board is told once (`task.commented`), and sees the comment with its pictures at once, never a comment and then its pictures. The alternative, a file uploaded first and named by a comment afterwards, leaves files that nothing refers to; the other, a comment and then its files one by one, shows the comment before its pictures and tells the board nothing of them.
4. **One address for every file of the project.** `GET .../files/<id>` serves a run's file, a comment's file and a page's file alike, since each is a file of the project under one id; a page's files keep their own address too. The command saves one on the agent's machine (`console file <id> [--out <path>]`), since an agent reads a picture with its own tools and never holds a token in its hands; the task and the run name the command beside each file.
5. **Pictures are seen where they are.** A picture among a comment's files is placed in the text as `![words](its name)`, and the pages show it there, over the project's own address; the files the text does not place follow it, pictures in place and the rest as links. Only the kinds a browser renders and cannot run are pictures (`image/png`, `image/jpeg`, `image/gif`, `image/webp`); the bytes are served never sniffed, under a policy that runs nothing, as every file is. The pages still show pictures from elsewhere over https only.
6. **The task's page reads one thread.** The comments, the runs and the decisions of a task are shown in the order they came, with the way to say something at the end, since a conversation reads in order; the runs and the decisions keep their cards. A report is the run's record, written by the agent at work; a comment is a word to the task's people: an answer to what they asked there, a question that is not a decision, a remark. The rules and the skill say which is which.

## Consequences

- People talk about a task where the task is, and the next agent reads it with the task: `console task` and `console take` print the discussion whole, each file with the command that reads it.
- A person can hand an agent a picture, and an agent can hand a person one, without a tool outside the board.
- `TaskView` takes `comments` and `onComment`, and its `fileHref` names a file by its id, since one address serves them all; `Markdown` takes `fileSrc` for the pictures a text names; `TaskThread`, `CommentCard` and `CommentForm` are exported for a console of one's own.
- A comment by an agent does not move its run's `lastHeardAt`: a comment needs no run, and a run's record is its reports. Whether it should, and whether a comment may be corrected or taken back, stays open.
- Rejected: comments as reports on a run (a person has no run; a report is the agent's record, not a conversation); the files of a comment as a page's files (a page is knowledge that outlives the run, a comment is a word about one task); an edit or a delete (what was read must stay what was said; the next comment corrects); files uploaded before the comment that names them (files nothing refers to).
