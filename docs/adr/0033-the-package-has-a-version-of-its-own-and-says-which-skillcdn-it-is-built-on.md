# ADR-0033: The package has a version of its own, and says which SkillCDN it is built on

- Status: Superseded by [ADR-0034](0034-the-package-is-versioned-on-skillcdns-line-one-line-at-a-time-with-a-patch-of-its-own.md), which returns to SkillCDN's line, adopted one line at a time
- Date: 2026-10-18
- Supersedes [ADR-0032](0032-the-version-is-skillcdns-with-a-patch-of-its-own-and-the-packages-are-taken-at-one-version.md); amends [ADR-0007](0007-the-package-is-published-through-trusted-publishing-and-versioned-on-the-core-line.md) (points 2 and 3, the version on the line of `@skillcdn/core`) and [ADR-0025](0025-the-command-names-its-version-on-every-request-and-the-console-holds-it-to-the-range-it-takes.md) (point 3, the range before 1.0). The line the console is built on is held by `scripts/check-skillcdn-line.mjs`; what a changeset says is in [AGENTS.md](../../AGENTS.md#workflow); what the API says is in [specs/rest.md](../specs/rest.md#get-apiv1me).

## Context

ADR-0007 gave `@skillcdn/console` the major and the minor of the `@skillcdn/core` it is built on, and ADR-0032 those of the one version the main repository's packages share since [its ADR-0058](https://github.com/skillcdn/skillcdn/blob/main/docs/adr/0058-the-published-packages-share-one-version.md), so that the number would say which SkillCDN the console goes with. A mirrored version has to be set, not bumped: changesets bump one step from the version there is and take no target, so a line the console skipped was written by hand and published at `.1`, and the same would happen again. Worse, the console's own breaking changes had no digit of their own: a minor named the line, so a patch had to say `Breaking:`, against the reading the main repository adopted, where a patch changes nothing that exists and a consumer takes it without reading.

Packages built on another package are versioned one of two ways. Most keep a version of their own and say what they go with as a dependency range and a table in the README; the ones that mirror the upstream version, the typings packages among them, compute the number with a publisher of their own rather than bump it. The console takes the first way: its tooling is made for it, and the information the number carried moves into data.

## Decision

1. **The version is the package's own.** Semantic versioning, read for a 0 major as the main repository reads it: a `patch` fixes and adds, and changes nothing that exists; a `minor` may change or remove a public surface, and its changelog entry says so first, as `Breaking:`; never a `major` while the major is 0, and `1.0.0` when the console's own contracts are declared stable, whatever SkillCDN's version is then. Every number comes from a changeset; none is set by hand. The number says nothing of SkillCDN: the console's 0.2 goes with SkillCDN 0.3, and the next line of SkillCDN is a `minor` of the console, whatever its number, since the shapes of `@skillcdn/core` the package passes on change with it.
2. **Which SkillCDN the console is built on is data.** The one version of the main repository's packages, declared at a caret range in every manifest of this repository (`^0.3.0`), resolved by the lockfile to one version, moved together (`pnpm -r update "@skillcdn/*"` for a patch of SkillCDN, `pnpm -r update --latest "@skillcdn/*"` for its next line) and held by `pnpm check`: the ranges name one line and the lockfile one version on it. The console tells it: `GET /api/v1/me` answers `console.skillcdn`, the line (`"0.3"`), read from the package's manifest with the version; `console whoami` prints it; the package's README keeps the table of which release goes with which SkillCDN.
3. **The command and the console, within a minor.** Before 1.0 the console takes a command of its own minor, whatever the patch (`>=0.2.0 <0.3.0`): a patch changes nothing that exists, so a command older than the console is answered and told once that a newer one exists, as from 1.0; one newer within the minor is answered and warned, as before; another minor is refused with `426`, as before. The policy of the `compat` module still raises the floor when a patch had to break something, and never widens the rule. From 1.0 the rule of ADR-0025 stands.
4. **What the promise covers:** the exports at the package's entry points, the REST API at `/api/v1` as [specs/rest.md](../specs/rest.md) has it, the arguments, output and exit codes of `console`, the variables of the image's configuration, the Node.js floor. A surface leaves in two steps where a release can afford it: marked `@deprecated` with what replaces it, removed in a later minor with a `Breaking:` entry; before 1.0 it may leave in one minor, said as `Breaking:`.

## Consequences

- No version is ever written by hand again, and no release says `Breaking:` in a patch. The check no longer reads the package's version; it reads the manifests and the lockfile, and fails when the `@skillcdn` ranges name two lines or the lockfile resolves two versions, naming the command that moves them together.
- Whoever installs reads the SkillCDN line from the README's table, from `console.skillcdn` or from `console whoami`, not from the number; a custom console compares `console.skillcdn` with the deployment it reads.
- A deployment of a patch no longer makes every agent's command update; a minor does, and the refusal names the command that does it, as before.
- The manifest goes back to the version the registry has, `0.1.24`: `0.3.0` was written by hand under ADR-0032 and never published, and the tooling computes the next number from the last one. The pending entries change what exists, so the next release is a minor, `0.2.0`, built on SkillCDN 0.3.
- Rejected: the mirrored version computed by a script of our own after `changeset version` (a publisher like the typings packages have: the changelog's heading would have to be rewritten too, and the console's own breaking changes would still have no digit); keeping ADR-0032 (a hand-written `.0` on every skipped line, and `Breaking:` in a patch); a range in the version number, `0.3.x` meaning "SkillCDN 0.3" by convention alone (what ADR-0007 wanted, and what the tooling cannot keep).
