# ADR-0010: The default UI's addresses name what they show, and every page and form has one

- Status: Accepted
- Date: 2026-10-10

## Context

The default UI routed a project's pages under `/p/<key>`, a letter that says nothing and that the REST API does not use. The forms (a new project, a new task, a decision raised, a page written or edited) opened in place with the address unchanged, so that a reload lost them and the back button could not return to them. On a project's pages the workspace's pages (the people, the tokens) sat in the same row as the project's, so that a click took the person out of the project without saying so. Links inside what people wrote (in a document, in a feed line, in a task) were followed by the browser as full loads while the navigation's own were followed in place, and the history was not one entry per step. Milestone 5 of the [roadmap](../roadmap.md) is for people who are not developers; the addresses and the navigation are the first thing they meet. This supersedes the UI paths of [ADR-0008](0008-a-workspace-holds-projects-and-what-a-person-may-see-and-change-is-decided-per-project.md) (point 6) and [ADR-0009](0009-documents-are-pages-of-markdown-in-a-project-addressed-by-path-versioned-and-linked-both-ways.md) (point 8); the rest of both stands.

## Decision

1. **A project's pages are under `/projects/<key>`**, the word the REST API uses (`/api/v1/projects/<key>`). The front page, `/`, lists the projects. The one name under `/projects/` that is not a key is `new`, the form; `new` is therefore not a key a project may have, and the schema refuses it.
2. **An address names what it shows.** A task by its number, as the command and people say it: `/projects/<key>/tasks/42`; a link by id is taken to the number's address. A decision by id: `/projects/<key>/decisions/<id>`, so that a feed line, a run and a page that refers to it lead somewhere. A document by its path: `/projects/<key>/docs/<path>`, a folder by its path, the root at `/projects/<key>/docs`. The workspace's pages at the top: `/people`, and `/agents` for the agents a person connected, which hold their tokens.
3. **Every form has an address.** Where the form makes something new in a space of its own: `/projects/new`, `/projects/<key>/tasks/new`, `/projects/<key>/decisions/new`, `/agents/new`. Where the thing addressed is free-form, a document's path or a task, a form is a way of showing the page and the query names it: `?edit` on a task or a page, `?ask` on a task (a decision raised about it), `?new` on a folder (a page written in it), `?version=<n>` on a page, `?q=<words>` on the documents (a search). The path says what, the query how it is shown; no segment of a document's path is reserved, so a page may be called `edit`.
4. **A form that made something is replaced in history by what it made**, and a cancelled form goes back to where it was opened from, or to its page when there is nowhere to go back to; the forms leave no entries behind.
5. **Two levels of navigation.** The header names the workspace and, on a project's pages, the project, as crumbs that lead to each. A row of tabs below it holds the pages of the level the person is on: a project's (Board, Docs, Decisions, Feed, Skills, Members, and Settings for an owner), or the workspace's (Projects, People, Agents). The person's menu at the end of the header leads to the workspace's pages from anywhere and signs out: the one way out of a project, and it says so by where it is.
6. **One history entry per step.** A link to one of the console's own addresses is followed in place, from one listener, wherever the link is: in a document, in a feed line, in a task, in the navigation. The same address again is no entry; a redirect, or an address normalized, replaces. The old addresses, `/p/<key>/...` and `/tokens`, are taken to the new ones while the 0.1 line lasts, so that links shared before keep working.

## Consequences

- A breaking change to the package before 1.0, released on the 0.1 line with a changelog that says so ([ADR-0007](0007-the-package-is-published-through-trusted-publishing-and-versioned-on-the-core-line.md)): `matchRoute` reads the query as well as the path and answers more kinds of route, `taskHref` takes a number, the task's and the document's forms are told what to show instead of deciding it, and the shell takes a menu beside its tabs.
- A custom console that composes the pages itself follows the same addresses, or its own; the components know nothing of them but the links they are handed.
- Links shared under the old addresses keep working through the redirects; a project with the key `new` cannot be made, and none was.
- Rejected: a project's pages at the root (`/<key>`), where every page of the workspace becomes a name no project may have, a list that grows with every page added, and a project made before a page was added takes the page's address, with the keys decided by the UI, which the API does not know of. Keeping `/p/<key>`: terse, and nothing a person can read. Forms as reserved segments inside a document's path (`/docs/<path>/edit`): a page may be called `edit`. The query for everything: `?project=web` is not an address a person reads or shares.
