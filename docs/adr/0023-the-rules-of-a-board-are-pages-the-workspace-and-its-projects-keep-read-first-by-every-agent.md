# ADR-0023: The rules of a board are pages the workspace and its projects keep, read first by every agent

- Status: Accepted
- Date: 2026-10-12

## Context

An agent at work on the board learned how the board is worked from the console's skills and what each task asks from the task. What the organization asks of every agent, and what a project adds (which skills to load first, where the work lives, how its pages are laid out, what may be decided alone, how to report), had no place of its own: the skills said an organization's own skill for its console would add it, which is a git repository served by SkillCDN, kept by a developer, not divided by project, and out of reach of the people who run the board. Rules for what an agent may decide alone were left open ([roadmap.md](../roadmap.md)).

## Decision

1. **The rules are pages of the board.** The workspace has rules, and a project adds its own: each a page of Markdown at the path `rules`, kept as a document is ([ADR-0009](0009-documents-are-pages-of-markdown-in-a-project-addressed-by-path-versioned-and-linked-both-ways.md)): versioned on every write, attributed to the person and the agent, archived rather than deleted. A project's rules are the page `rules` of its documents, written by an owner, kept out of the folders and the search, since they are the project's configuration and not its knowledge, and readable at its path, so that the links it makes hold. The workspace's rules are a page of the workspace's own: the same table with no project, the one such page until a decision widens them, written by an administrator. Links and files are a project's; a page of the workspace's own has none.
2. **The console's own rules hold until the organization writes its own.** The package carries the reference rules, true for any console as they stand; the server answers them for a workspace that wrote none (`source: "reference"`), and nothing of them is copied into a row, so that they change with the console's version. The console's own rules, written as they are, write nothing. Put away, the organization's rules give way to the console's own again; written again, the page comes back with its next version. A project adds its own rules or none: there is no default for a project.
3. **Who writes them is who configures:** an administrator the workspace's, an owner a project's, signed in or through their agent's token as [ADR-0021](0021-a-token-configures-as-its-person-does.md) says; a member's agent, which is most agents, is refused. Every version names who wrote it and through which agent, and the feed says so, since the rules are what agents are told. Everyone of the workspace reads the workspace's; whoever may see a project reads its rules.
4. **The surfaces.** `GET` and `PUT /api/v1/rules`, `POST /api/v1/rules/archive`, `GET /api/v1/rules/versions`; `GET /api/v1/projects/<key>/rules` answers both halves at once, and a project's rules are written as the page `rules` through the documents' routes. `console rules` prints what holds and `console rules write` writes; `console take` prints the rules with the task it took, since everything from there acts within them. The pages show the rules on the settings: a Settings page of the workspace, which the categories move under, and a project's, read by every member, with each form at an address of its own.
5. **The rules are the organization's layer; the skills are the craft.** The organization's skills, served by SkillCDN, say how work is done; the rules say what this board asks of agents, which skills to load first among them, and where its people's work lives; a repository's own agreement holds inside it. The console's skills no longer ask for an organization's skill for its console. The reference rules name the organization's skills in the terms of MCP: an agent reaches them through its own connection to the deployment that serves the address, which a person makes once, and loads one by its URI or with `load_skill` by its path.

## Consequences

- An agent has one place to start from on any board, and the organization and each project say in their own words what they ask, from the pages, without a repository or a developer.
- The rules are kept short (`MAX_RULES_LENGTH`), since every agent reads them with every task; what is long goes on pages the rules link to.
- An owner's agent can rewrite the rules it follows, as it can change whatever an owner can (ADR-0021); every version is kept with the agent named, and the reference rules say that an agent writes them only when a person asked for exactly that. A grant that would keep the rules to people alone is the shape to add should an organization need it.
- A closed network changes nothing: the reference rules name no address; the console's own skills are read from the package where the command is installed, which `console skills` says; the organization's skills are read through the deployment the console is configured with.
- The `documents` table takes a null project for the workspace's own pages, with a check that keeps them to the rules; migration 0015.
- Rejected: a column on the workspace and on the project (no versions, and a second shape beside the pages); the rules in the organization's skill repository alone (not per project, not editable from the board, and a developer and a SkillCDN connection needed to read what the board asks); seeding the reference rules into every workspace and project (copies that drift from the console's version); a prompt the console assembles from several pages (the console shows text and assembles nothing).
