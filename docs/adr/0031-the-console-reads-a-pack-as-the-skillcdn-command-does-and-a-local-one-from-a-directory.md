# ADR-0031: The console reads a pack as the `skillcdn` command does, a local one from a directory of its own, and passes the pack's answers on as they are

- Status: Accepted
- Date: 2026-10-18
- Builds on [ADR-0028](0028-the-console-reads-a-projects-pack-through-the-deployments-rest-api-with-a-pack-token-for-a-private-one.md) and [ADR-0015](0015-the-consoles-skills-live-in-this-repository-in-the-skillcdn-format-and-the-package-carries-them.md). The contract is in [specs/rest.md](../specs/rest.md#get-apiv1projectskeyskills) and [specs/cli.md](../specs/cli.md); what an operator sets is in [deploy/README.md](../../deploy/README.md#the-smallest-install-and-a-closed-network).

## Context

The console read a project's pack with a client of its own over the deployment's REST API, reshaped every answer into shapes of its own, and the command printed them in words of its own ([ADR-0028](0028-the-console-reads-a-projects-pack-through-the-deployments-rest-api-with-a-pack-token-for-a-private-one.md)). The main repository has since made the pieces it was imitating into published packages: the client of its REST API (`@skillcdn/client`, its ADR-0056), the reads over an index wherever it is kept (`@skillcdn/reader`, its ADR-0054), a directory read as a commit (`readDirectory` of `@skillcdn/indexer`), the REST bodies read back as the results they were made from and the renderers of what a model is given, taking the names of the reads (`@skillcdn/core`), and `local` addresses for a pack served from a machine with no deployment behind it (its ADR-0053, ADR-0055, ADR-0057). An organization in a closed network has no deployment to point the console at, and the smallest install should need nothing but the image, PostgreSQL and a directory.

## Decision

1. **The console reads a pack as the `skillcdn` command reads one.** A pack is opened for a request at its address, through a port shaped like the command's own: the five reads of the REST API (`mount`, `browse`, `find`, `skill`, `file`), answered in the shapes of `@skillcdn/core`, with a refusal carrying the API's code. The address of a git host is read at the deployment through `@skillcdn/client`, with the pack token the project holds as the bearer; the console's own client of the deployment is gone.
2. **A `local` address is read from a directory the console is given.** `SKILLS_DIR` names a directory laid out as `<owner>/<name>`, and `/local/<owner>/<name>` is the pack in it, read as the indexer reads a commit, kept as an index in memory for a minute, and read with the reader a deployment reads with: what the console answers from a directory is what a deployment would answer from the same commit. Whoever runs the console chose the directory: the pack is verified and served in full under its license, with no page at a deployment and no URI that means anything elsewhere. Without a directory, a `local` address is asked of the deployment, which may be a pack the `skillcdn` command serves over HTTP. A pack token goes to a deployment and never to a directory.
3. **The image carries the console's own skills as such a pack,** at `/app/packs/skillcdn/console` under `SKILLS_DIR=/app/packs`, so that an agent reads them through the console where no deployment is reachable; an organization mounts its packs beside it.
4. **The console's API passes the pack's answers on as they are.** The read routes answer the body the pack gave, as `@skillcdn/core` spells it (`RestSkill`, `RestBrowse`, `RestFind`, `RestFile`), in the console's envelope of address, where it is read, status and refusal; the listing keeps its items for the pages and carries the `mounts` answer (`RestMount`) for a program. The console reshapes nothing and keeps nothing.
5. **The command renders what a model is given.** `console skill`, `console skills <folder>`, `console skills --search` and `console skill --file` render the pack's answers with the functions a deployment's tools render for a model, naming the reads as the console's commands, after joining the pages a read came in; `console skills` prints what a client is told on connect and every skill and document, as `skillcdn skills` does. The console's own formatting of the pack is gone.
6. **The smallest install is a compose file:** the image next to PostgreSQL on one machine, the worker inside the api, the files in the database and the packs in a directory, with what a closed network carries in written down in the deployment contract.

## Consequences

- The console depends on four published packages of the main repository, by version, and its version follows core's new line; what it owed a deployment, parsing, error codes, a token sent to one origin, is the client's now, and a change to the API is a change to one client.
- An agent reads a pack the same way through the console, through the `skillcdn` command and over MCP: the same text, with the reads named for the way it has.
- A console with no deployment reachable serves its projects' packs from a directory, its own skills first; a pack in a directory is as current as its last synchronization, read again a minute after it changed.
- The console's REST contract for the pack changed: a custom console that read the old shapes reads the new ones, which are the main repository's.
- Rejected: keeping the console's own shapes and formatting beside the published ones (two renderings to keep in step, one of them an imitation); reading a directory only through a `skillcdn serve` sidecar (a second process and a second package for the smallest install, where one image reads the directory with the same packages); several directories or one per project (a root laid out as `<owner>/<name>` holds any number); a directory watched for changes (a minute's hold is what the public listing already had, and a cursor binds to a digest of the content, so an unchanged pack keeps its cursors).
