This changes the contract of the REST API, the client, the command and the default UI before 1.0:
  
  - **The API client.** The board's methods moved from `ConsoleClient` to `client.project(key)`, a `ProjectClient` of one project: `tasks`, `task`, `createTask`, `updateTask`, `decisions`, `decision`, `awaitDecision`, `raiseDecision`, `answerDecision`, `runs`, `run`, `startRun`, `report`, `handIn`, `handInFile`, `fileUrl`, `endRun`, `events` (now with a filter by `task`, `run` or `decision`), `eventStreamUrl` and `skills`, plus the project's own `get`, `update`, `members`, `addMember`, `updateMember` and `removeMember`. `ConsoleClient` gained `projects()` and `createProject()`, and its `events()` answers the workspace's own events, the ones about no project. The routes follow: `projectPath(key, collection, id)` builds `/api/v1/projects/<key>/...`, `REST_ROUTES` names only the workspace's resources, and `restPath` takes `people`, `tokens` or `projects`.
  - **The schemas.** `restProjectSchema`, `restProjectsSchema`, `restProjectInputSchema`, `restProjectPatchSchema`, `restMemberSchema`, `restMembersSchema`, `restMemberInputSchema` and `restMemberPatchSchema` are new, with `PROJECT_ROLES`, `PROJECT_VISIBILITIES` and the bounds `MAX_PROJECT_KEY_LENGTH`, `MAX_PROJECT_NAME_LENGTH`, `MAX_PROJECT_DESCRIPTION_LENGTH` and `MAX_SKILLS_ADDRESS_LENGTH`. An event carries `projectId` and `agent`: the agent the person acted through, named beside them on everything an agent did, a task edited as a run reported. `EVENT_KINDS` gained the `project.*` kinds, and `describeEvent` no longer says "(as ...)" itself: the feed shows the agent from the event.
  - **The command.** Every command on the board works in one project: `--project <key>`, else `CONSOLE_PROJECT`, else `.skillcdn-console.json` in the working directory or above it, which the new `console use <key>` writes; `console projects` lists the projects the person may work in. `CliIo` takes a `directory` store (`createDirectoryStore` from the entry point, a memory one in tests).
  - **The default UI.** The front page lists the projects; a project's pages are under `/p/<key>` (`matchRoute`, `projectHref`, and `taskHref(key, id)` now take the key). New components `ProjectList`, `ProjectForm`, `MemberList` and `ProjectRoleBadge`; `useConsoleData(client, projectKey)` loads the workspace once and the project the page is on, with its stream; `TaskView` takes `history`, everything that happened to the task, and `fileHref`; `RunCard` without `fileHref` names a file without linking it; `Shell` takes the `project` the page is on.
