**Pre-1.0.** Published from `main` by the release workflow, from changesets, through the registry's trusted publishing ([ADR-0007](https://github.com/skillcdn/console/blob/main/docs/adr/0007-the-package-is-published-through-trusted-publishing-and-versioned-on-the-core-line.md)). The version's major and minor are SkillCDN's, the one version of the main repository's packages the console is built on, and its patch the console's own: `@skillcdn/console` 0.3.x is the console for SkillCDN 0.3, and the changelog says what each release changed, first as `Breaking:` where it changed what existed ([ADR-0034](https://github.com/skillcdn/console/blob/main/docs/adr/0034-the-package-is-versioned-on-skillcdns-line-one-line-at-a-time-with-a-patch-of-its-own.md)). All three layers are here, and the command: the contract of the REST API, the components, the composition of the default console, and `console`, what an agent works the board with.

## What it exports

| Layer | What it is for | Status |
|---|---|---|
| The schemas and the client of the console's REST API | A custom UI talks to any console with types, and the contract has one source, shared with the server in `apps/console`. Also on its own at `@skillcdn/console/api`, which brings no React with it. | exported |
| The `console` command | The agent's side of the console: a thin client of the REST API, shipped as the package's `bin`, which a person signs in once with a token. Also as a function at `@skillcdn/console/cli`. | exported |
| The components: the board, a task, a run, a decision, the live feed | Each takes its data as props and nothing from the network. | exported |
| `createConsole(config)` | The default console assembled from the components, with the places a team may replace named. The UI the image serves is this, with the default configuration. | exported |
| The serving of a build | `@skillcdn/console/web`: the files of a build, the page for every other path, under one policy. What the image serves the default UI with, and what `console serve` serves a console of your own with. Node only. | exported |

### The API layer

```ts
import { createClient, restTaskSchema, TASK_STATES } from "@skillcdn/console/api";

const client = createClient({ baseUrl: "https://console.example" }); // the page's own origin when left out
const { items } = await client.tasks({ state: "ready" });
```

- **The vocabulary:** `TASK_STATES` (and `OPEN_TASK_STATES`), `TASK_PRIORITIES`, `GOAL_STATES`, `COLOR_NAMES` (the colours the pages paint; `CATEGORY_COLORS` is the same list), `PROJECT_ICON_TYPES` (the kinds of image a project's mark may be), `RUN_STATUSES`, `EVENT_KINDS`, `LINK_SOURCES`, with their types. One source for the database's constraints, the schemas and the board. With them, the rule of a document's path and of the links a text makes: `isDocumentPath`, `documentPathsIn`, `folderOf`, `nameOf`, `foldersAbove`, which the server records links by and the pages render them by. And a project's mark where it chose none: `projectColorOf` (a colour from its key, never gray) and `projectSymbolOf` (the first letter of its name).
- **The bounds** every input is held to (`MAX_TITLE_LENGTH`, `MAX_BODY_LENGTH`, `MAX_OPTIONS`, ...), so that a page can say so before a request is made.
- **The routes:** `REST_ROUTES` (the workspace's resources), `AUTH_ROUTES`, and the helpers that build a path (`projectPath(key, collection, id)` for everything under a project, `projectIconPath(key, icon)` for a project's image, `restPath`, `loginPath`, `signInPath`). The API itself is described in [docs/specs/rest.md](https://github.com/skillcdn/console/blob/main/docs/specs/rest.md).
- **The schemas,** in the mini build of zod, which runs in a browser: what the server answers (`restProjectSchema`, `restMemberSchema`, `restTaskSchema`, `restDecisionSchema`, `restEventSchema`, `restMeSchema`, ...) and what it is sent (`restProjectInputSchema`, `restTaskInputSchema`, `restTaskPatchSchema`, `restDecisionInputSchema`, `restAnswerInputSchema`, ...). Absent values are `null` on the wire, never missing keys. The server validates with the input schemas and is tested against the others.
- **The client:** `createClient({ baseUrl, fetch })` answers typed values parsed with those schemas, and throws an `ApiError` with the server's stable `code` (or `network`, `invalid_response`) for anything else. It takes a `fetch` and reads nothing else. With `userAgent`, every request names the client: the command sends `skillcdn-console/<version>`, by which the console holds it to the versions it takes ([ADR-0025](https://github.com/skillcdn/console/blob/main/docs/adr/0025-the-command-names-its-version-on-every-request-and-the-console-holds-it-to-the-range-it-takes.md)); `me()` answers the console's version and that range as `console`, and the `compat` module (`parseVersion`, `compareVersions`, `judgeClient`, `clientRange`, `commonRange`, `judgeConsole`, `consoleRange`, `userAgentOf`, `clientVersionOf`, the headers `VERSION_HEADER` and `CLIENT_RANGE_HEADER`, `CLIENT_POLICY`, the oldest command a console answers, by which the package narrows the common rule and never widens it, and `CONSOLE_AT_LEAST`, the oldest console the command works with; within a line of SkillCDN the two go together whatever the patch, and a release that changes what passes between them raises the floors, ADR-0038) is exported for a console or a script that compares itself with it. With `token`, a token a person made on their Agents page, every request carries `Authorization: Bearer` and no cookie: how a script or a console of a person's own acts as that person, configuring included (`createProject`, `updatePerson`, a project's `update`, `setIcon`, `addMember`, `updateMember` and `removeMember`, `createCategory`, `updateCategory` and `removeCategory`), within the person's own roles; only the tokens themselves and the approval of a connection are a session's, except that a token gives itself up with `giveUpToken` ([ADR-0021](https://github.com/skillcdn/console/blob/main/docs/adr/0021-a-token-configures-as-its-person-does.md)). The board is a project's: `client.projects()` lists those the person may see, and `client.project(key)` is the client of one, with its tasks, decisions, goals, runs, files, events, skills (`skills`, the pack by name and by count with its skills and, for a program, what the address serves as `@skillcdn/core` spells it; `skill`, `skillFile`, `skillBrowse` and `skillFind`, each answering what the pack answered as `read`, a `RestSkill`, `RestFile`, `RestBrowse` or `RestFind` of `@skillcdn/core`, with the pack's own refusal beside the status, ADR-0031), documents, settings, members and image (`setIcon`, `removeIcon`). `tasks(filter)` narrows the board (`TaskFilter`: a state, the open ones, a category's key, a goal, a worker, a day tasks are due by, and `q`, words of the title or a number, how a task is found by searching) and pages it (`Page`: `limit` and `offset`; the answer carries `more`), as `decisions(filter)`, `runs(filter)` and `goals(filter)` are paged; a task carries its `owner` and its `workers` (any number, ADR-0037), its `category`, `goalId`, its plan (`startsOn`, `dueOn`) and its moments (`startedAt`, `doneAt`). The roadmap is `goals(filter)` (`GoalFilter`: a state, the open ones, a category's key, `q` and a page), `goal(id)`, `createGoal` and `updateGoal`; the workspace's categories are `client.categories()`, `createCategory`, `updateCategory` and `removeCategory`; `client.work()` is what is on the person's plate across their projects ([ADR-0019](https://github.com/skillcdn/console/blob/main/docs/adr/0019-a-task-is-planned-in-days-the-board-keeps-its-moments-and-goals-and-categories-give-the-work-its-shape.md)). The documents go by path: `documents({ folder })` lists a folder, `documents({ q })` finds pages by their words, `document(path)` reads one with its links both ways and its files, `writeDocument(path, { title, body, baseVersion })` writes a version, `archiveDocument`, `restoreDocument`, `documentVersions`, `documentVersion(path, n)`, `attachFile(path, upload)` and `documentFileUrl(path, id)` do the rest; `updateDecision(id, { outcome })` grows a decision's record. The rules of the board ([ADR-0023](https://github.com/skillcdn/console/blob/main/docs/adr/0023-the-rules-of-a-board-are-pages-the-workspace-and-its-projects-keep-read-first-by-every-agent.md)) are `client.rules()`, `writeRules`, `archiveRules` and `rulesVersions`, for the workspace's, and a project's `rules()`, which answers the workspace's with the project's own; a project's are written as the page `rules`. `REFERENCE_RULES` is what holds where an organization wrote none, and `isReferenceRules` tells it from a text; `fillRules` fills `{language}` (`RULES_LANGUAGE_PLACEHOLDER`) with the name of a person's language, which `languageNameOf` gives from its tag. `agentLabel` is an agent's name before where it runs, what the pages show of "Claude Code on a laptop". `connect`, `connectRequest`, `approveConnection`, `denyConnection` and `claimConnection` are the two sides of an agent connecting with a code a person approves (ADR-0011), and `personTokens` and `revokePersonToken` an administrator's sight of everyone's agents. An `EventSource` cannot carry a header, so a stream read with a token is a `fetch` of `eventStreamUrl(after)`. `handInFile` sends a file as a form, and `fileUrl` says where its bytes are read back. `events(after, { task })` is everything that happened to one task.

### The command line

```sh
npm install -g @skillcdn/console                 # where the agent runs
console login --url https://console.example      # shows an address and a code; a person approves, and the token arrives here
console project new web "The web app"            # a project of your own, as on the pages; member, category and person role do the rest
console use web                                  # the project this directory works in; .skillcdn-console.json, committed; prints the sentence for AGENTS.md
console take 7                                   # a run begins on task #7 of the project, for the person the token is
console report "Found the cause: the parser trusts its input."
console hand-in ./report.md --label "the report"  # a file the console keeps, or an https link
console comment 7 "Which screen did you mean?" --attach ./shot.png   # a word in the task's discussion, with a picture; console file <id> reads one back
console skills                                   # the project's skills, with the URI to load each by
console rules                                    # what the organization and the project ask of agents; take prints them with the task
console ask "Keep the old behaviour?" --option "Keep it" --option "Change it"
console write notes/parser --title "The parser" --file notes.md   # a page of the project's documents, by path
console doc guides/onboarding                     # a page in full, with what refers to it
console finish --summary "Done: the parser refuses empty input."
console serve dist                                # a console of your own, built from this package, served for you
```

- **`console`** is the agent's side of the console ([docs/specs/cli.md](https://github.com/skillcdn/console/blob/main/docs/specs/cli.md)): a thin client of the REST API with no logic of its own, no dependencies beyond the package's, and no cost to an agent until it is used. The package states Node.js 24 as its floor and is tested on it; 22 runs the command today, checked by hand on each release. `console help` says everything an agent needs and `console --version` which version this is; `--json` answers with the console's own JSON; the exit code says whether the console did it (`0`), refused or could not be reached (`1`), did not understand (`2`), or a decision still waits (`3`), or the command and the console do not go together (`4`: the console refuses a command outside the versions it takes, and the command prints the update to make where it is installed, for the machine, in the project or fetched for the run; `console whoami` says both versions and the install, and a command behind or ahead within the range is told once a day on stderr).
- **A person signs it in once per console:** `login` checks the token against the console and keeps it as a login, with the console's address and the account, in `$XDG_CONFIG_HOME/skillcdn-console/credentials.json` (`~/.config` when unset); a machine holds a login per console and account, and a token goes only to the console that issued it. `CONSOLE_URL` and `CONSOLE_TOKEN` in the environment, together, stand in for a login at that address, for a hook or a job. A token is never taken on the command line.
- **Configuring, as the person** ([ADR-0021](https://github.com/skillcdn/console/blob/main/docs/adr/0021-a-token-configures-as-its-person-does.md)): `workspace`, `workspace edit`, `people`, `person role`, `person add`, `person remove`, `person deactivate`, `person reactivate`, `project new`, `project edit`, `project icon`, `members`, `member add`, `member role`, `member remove`, `category new`, `category edit`, `category remove` and `rules write` do what an administrator or an owner does on the pages, with the same refusals (`auth.forbidden` where the person may not), and the event names the agent beside the person. The tokens themselves have no command but `logout`, which gives the command's own up: they are made and removed on the Agents page, signed in.
- **The project's pack** is read as the `skillcdn` command reads one ([ADR-0031](https://github.com/skillcdn/console/blob/main/docs/adr/0031-the-console-reads-a-pack-as-the-skillcdn-command-does-and-a-local-one-from-a-directory.md)): `console skills` prints what a client is told on connect and every skill and document, `console skills <folder>` a folder whole, `console skills --search <words>` what the words find, `console skill <path>` a skill whole with its rules first, and `console skill --file <path>` a file, each rendered with the main repository's own renderers and the reads named as the console's commands, so that an agent reads here what it would read over MCP; a pack is at a SkillCDN deployment, or in a directory on the console's machine where no deployment is reachable.
- **The project's documents** are the agent's to read and write: `docs`, `doc`, `write`, `attach`, `archive` and `restore`, by path; a link in a body to a page's path refers to the page.
- **Every command on the board works in one project:** `--project <key>`, else `CONSOLE_PROJECT`, else what `console use <key>` wrote to `.skillcdn-console.json` in the working directory or one above it, a file meant to be committed. `console projects` lists the projects the person may work in.
- **`console serve [<dir>] [--port <n>]`** is for a person: it serves [a console of your own](#a-console-of-your-own) from your machine, the build in `<dir>` at `http://127.0.0.1:11197/`, and carries everything under `/api/` to the console the command is signed in to, with your token, which the pages never see ([ADR-0014](https://github.com/skillcdn/console/blob/main/docs/adr/0014-a-persons-own-console-is-served-from-their-machine-by-the-command.md)). The loopback only; a request from another site's page is refused. Without a directory only the API is served, for a development server.
- **`@skillcdn/console/cli`** exports `runCli(argv, io)`, the command as a function that takes its environment, its streams, its `fetch` and its credential store: what the integration tests run against the app with no socket, and what a console of a person's own could embed.

### The components and the composition

```tsx
import { createConsole } from "@skillcdn/console";
import "@skillcdn/console/console.css";

createConsole({
  title: "Acme", // until the server says what the board is called
  components: { SignIn: MySignIn }, // any of Shell, Board, TaskView, DecisionList, EventFeed, SignIn, TokenList, PeopleList, SkillList, ProjectList, MemberList, Calendar, GoalList, WorkList, CategoryList
}).mount(document.getElementById("root"));
```

- **The components** take their data as props and nothing from the network: `Board` (one column per state, the sooner due first; given `onMove`, a card is dragged to another column with a mouse, or with a finger that rests on it a moment first; given `editHref` and `onArchive`, each card has a menu with the way to the task's form and, once it is done or dropped, the way to put it away), `TaskCard`, `BoardFilters` with `filterTasks` and `byDue` (the board narrowed by category, goal, person and one's own), `TaskList` (tasks as rows, a page at a time), `TaskView` (one task with its plan, its moments, its workers, its decisions and its parts; given `parent`, the task it is part of when the page has read it, and `findTasks` and `findGoals`, its form searches), `TaskForm` (with the `categories` to choose from, the `people` to put on the task as its workers, and `findTasks` and `findGoals`, searches a page at a time by which the task it is part of and the goal it works towards are found, never offered whole, ADR-0037), `Calendar` and `Workload` with `workloadOf` (a month with each task across its planned days, a bar in a lane of its own, or on its one day, a due day or a start, the person who has each before its title, with a legend of the colours of the `categories` given, and who has what; `weekSegments` lays the bars; `TaskTip` is the task under the pointer in full, with the facts its page lists, within its item and above or below it as `placeTip` says, where there is more room, its goal named from the `goals` given; the composition narrows the page with `BoardFilters` as it does the board, the address carrying the filter with the month), `GoalList`, `GoalView` and `GoalForm` (the roadmap, one goal with its tasks by state, and the way to set one, with the `categories` to sort it into and its start and target days, ADR-0026), `GoalTimeline` with `timelineBars` (the roadmap as months: six from the month given, each goal planned in days a bar from its start to its target in the colour of its category, filled as far as its tasks are done, today marked, and the goals without days named below; `Calendar` given `goalHref` marks each goal's target day on the month), `WorkList` (a person's own work across projects), `CategoryList` (the categories, with the ways an administrator keeps them), `DecisionList` and `DecisionCard` (the waiting ones as cards, each with the way to answer, one of the options or a line of one's own; the answered ones as the record, `DecisionLog`, a row each with who asked and when, through which agent, the answer with the word given, marked when it is the person's own, and who answered and when, twenty to a page, each page at an address given `pageHref` and `page`, or turned in place), `DecisionForm` (about the task given as `taskId`, or one found by search through `findTasks`, a page at a time, ADR-0037), `EventFeed` (a sentence per event, newest first, a page at a time; `describeEvent` makes the sentence), `Shell` (the header with the workspace, the project, the tabs of the pages and the person's menu), `SignIn` (one button per provider the deployment offers), `TokenList`, `TokenForm` and `NewToken` (the agents a person connected, as the tokens they hold, the way to make one by hand, and the one just made with its secret shown once), `ConnectCodeForm`, `ConnectApproval` and `ConnectWords` (an agent connecting with a code: where the code is typed, what asks under it with the way to approve or refuse it, and what to tell the agent; `ConnectPage` composes the first two for a code), `PeopleList` (everyone in, with what each is and what let them in, the logins let in that nobody signed in with yet, and the deactivated, with the ways for an administrator to change a role, take a person out or back in, and take a listing away) and `ListingForm` (where an administrator lets someone in by login), `ProjectMark` (a project's mark: its own image when it has one, else its symbol on its colour, or the ones chosen from its key and its name; `sm`, `md` or `lg`), `ProjectList`, `ProjectForm` and `MemberList` (the projects a person may see with what they are in each, the way to make or change one, its mark included, with an image chosen for it (`onSubmit` gets the file, or `null` to take the image away), and those listed in a project with the way for an owner to add, change and remove them; `ProjectRoleBadge`, `PROJECT_ROLE_LABELS`, `VISIBILITY_LABELS` and `keyOf` with them), `PackTokenForm`, `PackConnect` and `PackTokenWays` (the SkillCDN token a private pack is read with: pasted, or connected with a code approved at SkillCDN, the console asked again at the interval the deployment named; and the two ways side by side, as a project's Settings page and the workspace's offer them), `WorkspaceSettingsView` and `WorkspaceSettingsForm` (the workspace's settings as rows: who sees whom, the day the week begins on and the time zone, picked by area with `timeZoneGroups`, `deviceTimeZone` and `offsetOf`), `SkillList` (a project's skills as SkillCDN serves them at its address, each with where a person reads it and what an agent loads it by, and how an agent is connected to it), `RulesView` and `RulesForm` (the rules of the board, ADR-0023: what holds and where it comes from, the console's own, a page written or none, with `{language}` filled with the language the pages speak, folded under its facts where asked, and the ways to write them, put them away and go back to the console's own for whoever may; the form starts from what holds and saves nothing that would change nothing), `FolderView`, `DocumentList`, `DocumentSearch`, `DocumentView`, `DocumentForm`, `DocumentFiles` and `DocumentCrumbs` (a project's documents: a folder's folders and pages, the way to find pages by their words, one page with its versions, what it links to, what refers to it and its files, a picture among them shown where the body names it, and the forms to write and attach, a picture pasted into the body attached once the page is written; `DocsPage` composes them for a path), `RunList` and `RunCard` (an agent's run on a task: what it reported, what it handed in, links and files alike, a picture among them small and large as a comment's is and placed in a report by its file name, what it waits for, and when an open one was last heard from; `RunStatusBadge` and `RUN_STATUS_LABELS` with them, and `fileHref` for where a file is read), `TaskThread`, `CommentCard` and `CommentForm` (the discussion on a task, ADR-0024: the comments, the runs and the decisions as one thread in the order they came, which `threadOf` orders, each comment with who said it, through which agent, its text with the pictures it names in place and its other files after it, pictures being what `isPicture` says, and the form at the end, where a picture pasted in goes with the comment; `TaskView` shows the thread given `comments` and `onComment`, and its `fileHref` names any file of the project by its id), and `Markdown`, which renders what people and agents wrote as elements, never as HTML, with links to the web only and pictures over https only, or, given `fileSrc`, from the file of that name, and, given `docHref`, a link to a page's path as a link to the page. `DecisionCard` reads as a record, with the context, the rationale and what followed, which `onUpdate` lets a person write. The small blocks (`Button`, `CopyButton` (a text put on the clipboard), `Badge`, `Avatar` (`xs` to `lg`), `PersonChip` with `personName` (a person by the name the host gives, the login where there is none), `Callout`, `EmptyState`, `Spinner`, `Time`, `Day`, `CategoryBadge`, `DueBadge`, `GoalStateBadge`, `ProgressBar`, `ShowMore` with `usePaged` and `PAGE_SIZE`, a long list growing a page at a time, `Pager` with `pageOf` and `RECORD_PAGE_SIZE`, a list turned by pages, `Picker` with `PICKER_PAGE_LIMIT`, one thing chosen out of a listing searched a page at a time and standing as a chip once chosen, and `Workers`, the people at work on a task as pictures side by side with a count of the rest), the words of the vocabulary (`STATE_LABELS`, `PRIORITY_LABELS`, `ROLE_LABELS`, with `RoleBadge`) and the day helpers (`today`, `addDays`, `daysBetween`, `monthGrid`, `formatDay`, `formatMonth` and the rest, days being the strings the API spells them as) are exported too.
- **The composition:** `createConsole(config)` returns `{ App, mount }`. `App` is the whole console as one component; `mount(container)` renders it and returns the way to take it down. `config.baseUrl` is the origin of the API (the page's own when left out), `config.components` the pieces to replace (`ConsoleComponents` names them with the props each takes), `config.languages` the packs the pages speak, `config.brand` the addresses of a symbol and a wordmark to show beside the name (ADR-0013; the default console passes those of `@skillcdn/brand`, the main repository's package of its marks), `config.client` a client of your own, for tests. The SkillCDN name and marks are trademarks of KDX Labs under the main repository's trademark policy, not under this package's MIT license; a custom console brings its own marks through the same slot. A console that holds a token rather than a session (one of your own, served by `console serve`) is told so by the API (`me.agent`, the token's name) and offers nothing a token cannot do: no agents page and no sign-out, since the tokens themselves are a person's own doing; everything else, configuring included, it does on the token as the person (ADR-0021), and it keeps the choice of language on the person. The pages route in the browser and every form has an address (ADR-0010): the projects at `/`, the person's own work at `/work`, the workspace's settings at `/settings` (its rules, its categories at `/categories`, where its skills come from), a project's pages under `/projects/<key>` (its roadmap, calendar and settings among them), a task by its number, a goal and a decision by their ids, a document by its path, and the query for how a page is shown, the board's filters, the calendar's month, the week of the person's work and the settings' forms among it (`matchRoute(pathname, search)`, `PATHS`, `projectHref`, `boardHref`, `taskHref`, `goalHref`, `calendarHref`, `workHref`, `personWorkHref`, `decisionHref`, `docHref`, `settingsHref`, `projectSettingsHref`, `newTaskHref`, `newGoalHref`, `newDecisionHref`, and `movedFrom` for the addresses of before); every link to one of them is followed in place, with one history entry per step; the workspace is loaded once and the project the page is on whole, kept current by the project's stream (`useConsoleData(client, projectKey)`, for a composition of your own).
- **Pages of your own:** `config.pages` adds tabs beside the console's. Each is a `CustomPage`: a `key` (what the address says: `/pages/<key>` on the workspace, `/projects/<project>/pages/<key>` on a project), a `label` (one word, or a word by language tag with `en` standing in), a `level` (`workspace`, or `project` for a tab on every project), `wide` for a page that takes the whole window, and `render(context)`, which gets what the default pages get: the `data` of `useConsoleData` with its actions, the `project` the page is on, the `client`, the `navigation`, the `words` and the `language`. `customPageHref` names the address and `customPageLabel` the tab's word. A page that is not among the pages given shows nothing there.
- **The languages:** every word the pages show is in a pack (`Messages`, keyed as `en` is), English and Korean ship (`ENGLISH`, `KOREAN`, `DEFAULT_LANGUAGES`), and a component takes its words from the language above it (`useWords`, `useLanguage`, `LanguageContext`), English where there is none. The person's choice is kept on them (`client.updateMe({ language })`) and the browser's languages decide before one (`chooseLanguage`, `packFor`). `createConsole({ languages })` replaces the packs the default console speaks, so that a custom console adds a language of its own; a pack is complete by type.
- **The styles** are one file, `@skillcdn/console/console.css`: the tokens (`--sc-*`), a small reset, and one class per block, all prefixed `sc-`. The look is SkillCDN's own, on a light ground ([ADR-0040](https://github.com/skillcdn/console/blob/main/docs/adr/0040-the-pages-are-light-by-default.md)): one accent, the page a pale field with a light in it (the shell, `sc-shell`, paints it) and the surfaces panes of frosted glass over it (`--sc-glass-*`). A console that wants the dark look of 0.3.2 and before sets the colour tokens below back to its values and `color-scheme: dark` on `:root`, and passes a light wordmark. Re-skinning starts and mostly ends with the tokens; a custom console that wants a flat page sets the field's colours to one and the glass to none. A stylesheet of your own, loaded after this one, sets them on `:root`: the surfaces (`--sc-color-bg`, `--sc-color-bg-subtle`, `--sc-color-bg-inset`, `--sc-color-bg-raised`, the borders), the text (`--sc-color-text`, `--sc-color-text-muted`, `--sc-color-text-faint`), the accent and the point (`--sc-color-accent*`, `--sc-color-point*`), the tones (`--sc-color-success`, `--sc-color-warning`, `--sc-color-danger`, each with a `-subtle`), the field and its light (`--sc-color-sky`, `--sc-color-far*`, `--sc-color-light-*`, `--sc-color-vignette`), the glass (`--sc-color-glass*`, `--sc-color-sheet*`, `--sc-color-field`), the fonts (`--sc-font-sans`, `--sc-font-mono`) and the radii (`--sc-radius-*`); the categories' colours are `--sc-category-line` and `--sc-category-fill` under `.sc-category-<name>`. Beyond the tokens, every block has its class (`sc-panel`, `sc-card`, `sc-column`, `sc-header`, ...), which a stylesheet of your own may style; the classes are part of the package's surface, and a change to one is in the changelog. The faces are the page's to provide: the stylesheet names Pretendard first for the Korean and falls through to the system's faces, and the default console loads it; a custom console loads what it likes.
- React 19 is a peer dependency; `react-markdown`, `remark-gfm` and `@skillcdn/core`, for the pack's shapes and the renderers of what a model is given, are the package's own.

A custom console is a small repository that depends on this package, holds a configuration and a CI job, and builds to static files: the organization's, served by the image from `WEB_ROOT` in place of the default UI, or your own, served by `console serve` on your machine. Nothing of the server is in the package but the serving of a build, `@skillcdn/console/web`, which the image and the command share.

### A console of your own

A console you build from this package and run for yourself, against your organization's console, with the pages and components of your choosing ([ADR-0014](https://github.com/skillcdn/console/blob/main/docs/adr/0014-a-persons-own-console-is-served-from-their-machine-by-the-command.md)). It is a small repository of your own, in the shape of the default console (`apps/console/web` in the console's repository: one page, one script, one build):

```sh
npm install @skillcdn/console react react-dom
npm install --save-dev vite @vitejs/plugin-react typescript
```

```tsx
// src/main.tsx: the composition, with a configuration of your own
import { createConsole } from "@skillcdn/console";
import "@skillcdn/console/console.css";

const container = document.getElementById("root");
if (container === null) {
  throw new Error("the page has no #root element");
}
createConsole({ title: "Mine" }).mount(container);
```

```ts
// vite.config.ts: while building, the development server sends the API to console serve
import react from "@vitejs/plugin-react";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [react()],
  server: { proxy: { "/api": { target: "http://127.0.0.1:11197", changeOrigin: true } } },
});
```

```sh
console login --url https://console.example      # once: the token an agent of yours would hold serves your console too
console serve                                    # the API alone, at http://127.0.0.1:11197/api/, for the development server
npx vite                                         # your pages, reloading as you build them
npx vite build && console serve dist             # the build served whole, at http://127.0.0.1:11197/
```

The pages run on your token: what you may do on the board, they may do, and no more. The token never reaches the browser; the command adds it on the way, on the loopback only, and refuses a request from another site's page. The tokens themselves are made and removed on the organization's console, signed in, and the pages say so there; everything else, configuring included, the pages do on your token as the organization's console does on your session. Replace a component, pass your own language pack or your own marks, or compose pages of your own from the components and `useConsoleData`: the sections above say what each piece takes.

### The skills, for an agent

What an agent reads to work the board, to build a console or to deploy one is in the console's repository as skills in the SkillCDN Format ([ADR-0015](https://github.com/skillcdn/console/blob/main/docs/adr/0015-the-consoles-skills-live-in-this-repository-in-the-skillcdn-format-and-the-package-carries-them.md)), served by SkillCDN at `skillcdn.ai/gh/skillcdn/console` with the architecture, the decisions and the specifications, and shipped in this package: `skills/working-the-board/SKILL.md`, `skills/building-a-console/SKILL.md`, `skills/deploying-a-console/SKILL.md` with its references and scripts, their manifest `SKILLCDN.md` with the rules they share, the specifications they point to under `docs/specs/` (`rest.md`, `cli.md`), and the sources under `src/` without the tests, so that `npm install` brings what an agent needs to read, at the version installed. Point an agent at them in `node_modules/@skillcdn/console/`, or copy a skill's folder into the agent's own skills. A project of a console may name that address as its skills address, and an organization's own skill for its console adds its rules and links these. The skills are maps: what they name, this README, the types and the specifications say in full.

## Rules

Read the root [`AGENTS.md`](../../AGENTS.md) first. This package is what other people install; it is their contract.

- **Pure where it can be.** The schemas and the components do no I/O; the client takes a `fetch` and a base URL; the command takes everything it needs through `runCli`. Nothing here reads the environment but the command's entry point, `src/cli/main.ts`, the one place the process is read (lint enforces it).
- **The main repository's packages come from npm,** by version: `@skillcdn/core` here, for addresses, the REST shapes of a pack and the renderers of what a model is given; the client, the indexer and the reader in the app. Never a path into the main repository, never a copy of its code ([ADR-0001](../../docs/adr/0001-the-console-is-the-reference-console-built-on-the-published-packages.md), [ADR-0031](../../docs/adr/0031-the-console-reads-a-pack-as-the-skillcdn-command-does-and-a-local-one-from-a-directory.md)).
- **Exported types are public contract.** A change to what `src/index.ts` exports carries a changeset written for whoever installs the package, and the README changes with the usage.
- **Runtime dependencies need a reason.** This package ships to browsers; a dependency here needs a stronger case than anywhere else in the repository.
