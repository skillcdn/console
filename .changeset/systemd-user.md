`console agent setup` keeps a runner running on Linux too (ADR-0085): the `systemd-user` service, a unit of the agent's own OS account, `~/.config/systemd/user/skillcdn-console-runner.service`, turned on and started by that account's own systemd with no administrator's rights; its lines are in the account's journal. Setup asks for lingering for the account itself, so that the runner outlives the account's session and starts with the machine; where a system keeps that for an administrator, setup says what is left to do. `console agent setup --refresh` has the system read a unit it wrote again, which ends nothing that runs. Run on Ubuntu 24.04 with systemd 255: the unit loaded, the runner heard from, and started again after it ended. For whoever builds on the runner: `systemdUser`, `systemdUnit` and `SYSTEMD_UNIT` in `@skillcdn/console/runner`; a service's command may carry what it adds to the environment, what is left to do where it may fail and did, and how often it is tried, and a service may name the commands that have the system read its files again (`ServiceCommand`, `ServicePlan.reread`).
