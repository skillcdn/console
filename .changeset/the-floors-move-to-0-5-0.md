Breaking: the console takes commands from 0.5.0 on, and the command consoles from 0.5.0 on (ADR-0038, ADR-0043): both floors move to the first version of the line, once for the whole of the agent accounts (ADR-0084 to ADR-0089) and for SkillCDN 0.5, so that an agent's machine updates its command once, with the deployment. A console from 0.5.0 answers a command of the line before with `426` and `client.outdated`, naming the version to install (`npm install -g @skillcdn/console@latest`), and a command from 0.5.0 refuses a console of the line before itself, naming the command that goes with it. What an older command's reader would refuse: the events `person.updated`, a member's title or an agent account's persona changed, with `fields`, and `agent.state_changed`, how an agent account stands now, with `handle`, `state`, `was` and `detail`; and a claim of a connection that answers `signed_in` with a session, for a command that asked to be the account itself (`as: "self"` on `POST /api/v1/connect`). What is added and read as optional: `kind`, `handle`, `title` and `avatarParts` on a person, and `as` on a connection. The schemas `restAvatarPartsSchema`, `PERSON_KINDS`, `AGENT_STATES` and `CONNECT_AS` are exported for whoever builds a console; `describeEvent` words the two kinds in English and Korean. The REST snapshot is taken again at the floors.
