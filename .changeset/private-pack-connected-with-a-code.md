A private pack is connected with a code a person approves at SkillCDN (ADR-0036), in place of a token pasted: `POST /api/v1/projects/<key>/pack-token/connect` asks the deployment to connect the project's address as the `skillcdn` command does and answers the code and the page the person is shown (`restPackConnectStartedSchema`); `GET .../pack-token/connect` says how it stands, `none`, `pending`, `connected` with the project once the token is kept, or `ended` with why (`restPackConnectSchema`, `PACK_CONNECT_ENDINGS`); `DELETE .../pack-token/connect` gives it up. The client gains `connectPackToken`, `packTokenConnection` and `cancelPackTokenConnection` on a project; the Settings page's pack token form connects first, with `PackConnect`, which asks the console again at the interval the deployment named, and pastes second; `console project pack-token <key> --connect` prints the page and the code and waits for the approval. The refusals are `project.pack_connect_unsupported` and `project.pack_connect_refused`, beside `skills.unavailable`. The paste stays for a token made by hand.
