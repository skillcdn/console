`console agent setup --console <origin> --code <code>` makes a machine an agent account's (ADR-0088), from the line of its invitation, in the agent's OS account and with no administrator's rights. After the guide it signs the command in as the account: the page opens in the machine's browser, the account says there that the command is it, and a sign-in that turns out to be anyone else's is given up with nothing set up. It then settles the desk, which is left as it is where there is one, cloned from the git host where the account pushed one before, with its own `git.token` handed to git in the environment, or written from the template over no file that is there; writes the service that keeps the runner running, `launchd` on macOS, and loads it; and says whether the runner is heard from, with the machine and the OS account, which the account's page shows beside the session. `--guide` prints the guide alone, `--desk <dir>` names the desk, `--new-desk` begins a new one, `--no-service` writes no service, and `--refresh` derives the machine again when the services or the account changed. The `launchd` service is written from the system's documentation and was not run on a Mac yet. For whoever builds a console: `launchd`, `launchdUnit` and `LAUNCHD_LABEL` in `@skillcdn/console/runner`, the `Service` interface with its `ServiceInput` and `ServicePlan`, `deskRemoteOf`, and `deskRemote` on a `ServiceProvider`.
