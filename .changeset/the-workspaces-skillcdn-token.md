The workspace holds a SkillCDN token of its own (ADR-0036): every project that names no address of its own and holds no token of its own reads the organization's pack with it. `PUT` and `DELETE /api/v1/workspace/pack-token` set it and take it away, and `POST`, `GET` and `DELETE /api/v1/workspace/pack-token/connect` connect it with a code a person approves, all for an administrator (`REST_ROUTES.workspacePackToken`, `restWorkspacePackConnectSchema`; the refusals `workspace.pack_token_refused`, `workspace.pack_token_unsupported`, `workspace.pack_connect_refused` and `workspace.pack_connect_unsupported`); `me.workspace.skills.packToken` says when it was set (`restWorkspaceSchema`, optional for an older console). The client gains `setWorkspacePackToken`, `removeWorkspacePackToken`, `connectWorkspacePackToken`, `workspacePackTokenConnection` and `cancelWorkspacePackTokenConnection`. The Settings page's Skills section shows the token, and an administrator sets it at `/settings?pack-token` on `PackTokenWays`, the two ways to a token side by side, which the project's page shares (`PackConnect` takes a `PackConnectState` and calls `onConnected` with nothing; `PackTokenForm` takes `setAt`). The command gains `console workspace pack-token --connect|--stdin|--remove`. Wherever people read it, the pack token is called the SkillCDN token; the API and the command keep `pack-token`. The setting of who sees whom is called the member visibility on the pages, and its values read as a scope.
