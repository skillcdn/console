An agent works a plugin through the command (ADR-0053, `docs/specs/plugins.md`, "The command"): `console plugins` lists the plugins one may use, `console plugin <key>` one with its commands, `console plugin <key> help <command>` one command in full, and `console plugin <key> <command> [args]` runs it, the words sent as typed to `POST /api/v1/plugins/<key>/invoke`, which parses them against the definition (`parseArgv`, from `@skillcdn/console/plugin`), `--file <path>` or `-` uploaded first and `--run <id>` naming the run the command is written on; exit `3` when the command raised a decision. `records`, `skills` and `skill` read a plugin's records and its own skills, and `enable`, `disable`, `settings`, `secret`, `grant` and `revoke` are an administrator's. The rules carry the plugins: `GET /api/v1/rules` and a project's rules answer `plugins`, which `console take` and `console rules` print under `## Plugins`. New shapes, all additions: `restPluginInvokeInputSchema`, `restPluginCommandInputSchema`, `restPluginInvocationSchema`, `restPluginFileHandleSchema`, `restPluginRecordSchema` with its page, read and versions, `restRulesPluginSchema`; `RestPluginDetail` gains `boardDefaults`; the client gains `plugins()` and `plugin(key)`. An argument of a command is not named `json`, `url`, `account`, `project`, `file` or `run` (`RESERVED_ARG_NAMES`); `PLUGIN_ENDPOINT_MS` bounds an endpoint, which a console answers at `ANY /api/v1/plugins/<key>/x/<name>` for a person or a webhook.
