`console agent setup` keeps a runner running on Windows too (ADR-0085): the `task-scheduler` service, a scheduled task of the agent's own OS account, `SkillCDN Console Runner (<account>)`, registered by that account with no administrator's rights and started when it logs on, so that the runner runs while the account is logged on at the machine. The task starts the runner in the desk, in no window, with the `PATH` setup ran with, keeps its lines in `~\AppData\Local\skillcdn-console\runner.log`, and starts it again ten seconds after it ends; ending the task ends the runner, and one runner runs for the account. `console agent setup --refresh` registers a definition it wrote again, which ends nothing that runs. Run on Windows 11: the task registered and started, the runner heard from, a turn of Claude Code under it, the runner started again after it ended and ended with the task. `console runner` ends when the process that keeps it does, where its environment names that process (`CONSOLE_RUNNER_KEEPER`), which is how a task that the system ends by its one process takes the runner with it. For whoever builds on the runner: `taskScheduler`, `taskDefinition`, `taskScript`, `taskNameOf`, `TASK_NAME` and `KEEPER_VARIABLE` in `@skillcdn/console/runner`; what a service is told of the runner now names the OS account too (`ServiceInput.user`).
