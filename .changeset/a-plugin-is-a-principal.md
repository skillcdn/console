Breaking: a plugin that calls another plugin from its own job, hook or webhook no longer runs the callee with every role; the callee sees `{ kind: "plugin", plugin, roles, for: null }`, the calling plugin with the roles an administrator granted to it and the callee's default role (ADR-0072). A role may be granted to a plugin (`POST .../grants` with `plugin`, `console plugin <key> grant <role> --plugin <key>`, the settings page; `RestPluginGrant.plugin`, read as optional); a manifest asks for them with `grants: { <key>: { roles, why } }`, offered when enabling and listed on the plugin's page, answered as `asks` on `GET /api/v1/plugins/<key>`, and read by the plugin as `ctx.plugin.grants`. With the capability `people:act` a plugin acts for a person who did something elsewhere: `ctx.plugins.get(key).for(personId)` calls the other plugin with the roles both hold, in the person's language, and `ctx.console.decisions.answer(id, { optionKey | option, note? }, { for })` answers a decision by the person's own standing; the event names the person, the plugin and, as `via` (read as optional), the plugin that acted for them, and the feed says "through <plugin>". `PluginCaller` gains the kind `plugin` (`PluginAsCaller`), `createTestContext` takes `plugins` with `for`, and a plugin with `plugins:<key>` hears that plugin's `plugin.enabled`, `plugin.disabled` and `plugin.upgraded` in its hooks.
