Breaking: a secret no longer comes back to a plugin in an answer (ADR-0070, amended by ADR-0075). Sealing fails closed: where `seal` names values, an answer that is no JSON object or array reaches the plugin without its body, where it reached it whole before, a token endpoint's form with the token in it; a value that is no string, is over 4,096 characters or holds a secret the request carried from another setting is never sealed and reads `"[withheld]"`; and the answer carries `sealed`, what became of each value named (`sealed`, `absent`, `not_a_string`, `too_long`, `echoed`, `not_json`; `PluginFetchResponse.sealed`, `SealOutcome`), so that a plugin tells a token sealed from one it never received. A secret pinned to `hosts` is sealed from their answers alone, `plugin.forbidden` before the request goes out otherwise, so that another host cannot put a token or a signing secret of its own in its place. `ctx.fetch` takes `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE` and `OPTIONS` alone, `TRACE` and any other being `plugin.invalid_args`; and every form of a secret the console put into a request, as placed, escaped as JSON, URL-encoded, and for `basic` the base64 of the pair and the password, is taken out of the answer's headers and body, as is a value sealed or withheld wherever else the answer holds it, so that a server that echoes the request, or a redirect whose `location` carries a `query:` secret, hands the plugin `"[withheld]"`.
