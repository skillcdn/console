# Work given in chat

Work of a project that a person gives in chat, naming no task, goes on the board before it is done, unless the board's rules say otherwise. Read the rules first, `console rules`, since no take has printed them. Look for the work on the board, `console tasks --search <word>`, by one word a title would hold, a file's name or the thing's, in the language the board is written in, since every word given must be in the title: a task that is there for it is the one to take. Where none is, write it and take it in one command, `console task new "<title>" --body <markdown> --category <key> --take --rules <mark>`, the key one of `console categories` and the mark the one the rules were printed under, and tell the person the number it printed. A task that was there is taken by its number, with the same mark (`console take <number> --rules <mark>`). Then work it as the skill's workflow says.

One piece of a project's work goes on the board first, as said above. Several tasks to write, a goal or the project's own set-up is [planning-the-board](/skills/planning-the-board/SKILL.md); a plan asked for as the work itself (a plan for payments, for a launch) is one piece of work, done here; a task whose body asks for the project itself (a member, a category, the rules, a goal) is worked as a run all the same, with that skill's commands. What a member does in their own desk for themselves, its setting-up, a record, a page, is on no board unless they say to put it there: no task is written for it, and the person is not asked whether to.
