# What the work needs, and what to do when it is missing

| Need | How | When missing |
|---|---|---|
| The `console` command, signed in | `console whoami`, before the first step; it changes nothing on the board. | Stop and tell the person what to do: `npm install -g @skillcdn/console`; `console login --url <the console's address>`, which shows an address and a code the person approves on the console's own pages. Never look for a token. A command refused because its person is out (`auth.deactivated`, `auth.not_admitted`) starts nothing, and the person is told. |
| The right project, at the right console | `whoami` names the project and what named it: `.skillcdn-console.json` in this directory or one above it, which `console use <key>` wrote with the project and the console's address; `CONSOLE_PROJECT`; or `--project`. Where the repository's agreement names its project, the two are the same; a checkout whose agreement names a project and that nothing binds yet, a fresh clone of a public repository, is bound once with `console use <key>`, said in a line. A directory of no repository, a new folder or a desk, names no project: every command of the board there says `--project <key>`. | `project.not_found`: this console has no project of that key, or it is not this person's to see. Stop, and tell the person the key, the console, what named it and the two things they can do: an owner of the project lists them in it, or the directory is bound to the right key. Where they name the key, or hand the choice back and the repository's agreement names it, bind to that key (`console use <key>`) and say so at once and again at the end; never to any other key, and where neither names one, stay stopped. A project other than the one the agreement names: say which of the three decides, and stop. A console the directory names and nobody is signed in to here (`console logins` lists those that are): the person signs in there. |
| The command at a version the console takes | Refused as too old or too new, the command exits with `4` and says which of the two to update, and how. | Run the update of the command, then go on; where the console is the one to update, or the machine refuses the update, stop and tell the person. A line on standard error that a newer command exists, while the console still answers, is left for later. |
