# Preparing the machine

**The person's part** is what only a person does:

1. **An OS account for the agent,** apart from anyone's, on a machine that stays on. Whether it holds an administrator's rights is for whoever keeps the machine to say: an agent that is to install and update what it needs usually does. The computer the console itself runs on will do, a trial's say: the agent has an OS account of its own there all the same, the console's address on it (`http://127.0.0.1:<port>`) is every account's of that computer, and the agent's account stays logged in beside the person's (switch users, never log it out).
2. **Logged in when the machine starts.** The runner is the OS account's own service, which needs no administrator: a launch agent on a Mac and a scheduled task on Windows, which run while the account is logged in, so set the machine to log it in. A Mac logs one account in by itself, and none while FileVault is on: where several agents share one, choose which account that is and who logs the others in after a restart; and giving FileVault up for it leaves the disk readable by whoever takes it, which is for whoever keeps the machine to weigh. On Linux a unit of the account's own systemd, which starts with the machine once lingering is on (setup asks for it, and says where an administrator has to: `sudo loginctl enable-linger <account>`).
3. **The product, signed in with the agent's own subscription,** in that OS account: Claude Code, Codex, or another that speaks the Agent Client Protocol. Codex is run as its app server, and takes a build of 0.139.0 or later: keep it current.
4. **The line,** said to a session of the product there. Then sign in when asked, yourself, in the browser the command opens. Never write a password in the chat.

**The session's part** is the machine's least. The line says to install what is missing without asking, Node.js 24 or newer and the command first, and to run `console agent setup --console <origin> --code <code>` ([the command](/docs/specs/cli.md#setting-a-machine-up)), which:

1. **Looks at the machine first** and says everything that is missing at once, with what installs it: git (on a Mac the Command Line Tools, without which `git` only opens a window), the product's command, and for Claude Code the agent's browser ([ADR-0151](/docs/adr/0151-an-agents-browser-is-a-chrome-with-no-window-unless-its-desk-names-the-products-own.md)): Google Chrome, and `chrome-devtools-mcp`, the program that drives it with no window (`npm install -g chrome-devtools-mcp@latest`, on Node.js 22.12 or later: under an older one npm installs a version too old to use). Install each, without asking, and run the line again. Such a browser needs no screen, no extension and no sign-in of its own. `--browser chrome` is for Claude Code's own browser tool instead, in a Chrome with a window: the Claude in Chrome extension is then installed in that browser too, signed in as the agent's subscription account. `--no-browser` is for an agent that signs in at no page, whose desk then names `"none"`, and `--driver` names the product where both are there.
2. **Asks to be signed in as the account.** It opens the console in the machine's browser and waits. Say to the person at the machine which login to sign in as and the code the page must show: they sign in themselves, and say that it is them. A sign-in that is anyone else's is given up, and nothing is set up.
3. **Settles the desk,** `desk` in the OS account's home: one that is there is left as it is, one the account pushed before is cloned, otherwise the template is written ([the desk](/docs/specs/runner.md#the-desk)), its `runner.json` naming the product and the browser found. The desk's git is set to read `git.token` from the account's store when the git host asks, so nothing is typed and no keychain keeps a copy.
4. **Writes the service, starts the runner,** waits for the agent's first session, and says where to watch it. The runner holds the machine awake while it runs, with no setting changed, and its own lines say whether that holds; a lid that is closed or a sleep someone asks for still ends it. On a Mac it ends with the settings that would still leave the agent unheard with nobody there, each with what to change and its cost: read them to the person who keeps the machine, since they take an administrator and the choice is theirs.

**Then stop.** The agent's sign-ins, its tokens, its desk's repository, its profile and its messenger are the agent's own, done in its own session with its own instructions: a session at the machine that goes on does them twice and worse. What you change on the machine afterwards, say to the agent: `console agent wake me "<what changed>"`.
