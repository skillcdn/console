# What was not seen run yet

On 2026-11-20 an agent account was set up on a Mac from the invitation's line and worked a day against a live console: the `launchd` service, the `claude` driver with Claude Code 2.1.329 and its browser tool, a desk pushed with the account's own token, and the `slack` wake source. What that day asked for is in this skill and was written after it, tested against invented fixtures and not yet run on a machine: the look at the machine before the sign-in, the desk's git reading the store, what a setup ends with, the helper that holds a Mac or a Linux machine awake (the one for Windows was run on Windows 11), a `runner.json` taken while the runner runs, a wake kept for later, what a runner says of a time it did not run in, what a setup reads of a Mac's settings, a new conversation an agent begins for itself, what a wake from Slack says of an account of another workspace and of a conversation shared with another organization, a wake that carries what was said before it, a message someone passed on and who else is there, read by an agent (the reads of a conversation, and `console agent messages`, were run by hand in a workspace), and your status at Slack while you work, which is written from the messenger's documentation and from what a trial found of it. A browser with no window was run on a Mac, by hand: Claude Code 2.1.330, started with the server as the driver names it, opened a page in a headless Chrome, read its title and saved a picture of it (`chrome-devtools-mcp` 1.13.0), and the same with its window; and on Windows through the driver, with no window and with one (Claude Code 2.1.322, the program at 1.14.0). It was not run on Linux, nor through a setup and a runner. Also not seen: a desk cloned with the account's token on a second machine, an account logging on to Windows after a restart, an agent account run on the computer its console runs on, in a second OS account beside a person's, and any product behind the `acp` driver but the adapters of Codex and Claude Code. Codex takes a message while a turn runs, as Claude Code does: seen with a signed-in Codex on Windows, under the driver and not under a runner. Behind the `acp` driver a message waits for the turn's end, so several tasks are worked there in short turns with a wake of your own between them ([several tasks at once](several-tasks.md)), which was written from the driver and not seen run. [The roadmap](/docs/roadmap.md) lists each as open. Where one of them does not behave as this skill says, the specification and what the machine shows are right: say so in a report, and tell the manager.
